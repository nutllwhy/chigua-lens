## Demo 要准确说明什么

项目包含两个不同层次的入口，不要混在一起宣传：

- **网页 Demo**：一个固定虚构案例的概念体验，展示时间线、证据分级、来源详情和长图形态；它不实时抓取微博，也不处理任意输入。
- **Codex Skill**：真实热点的工作流入口，接收热搜词、微博链接、截图或本地材料，生成九页 PPT、信源台账与 `dossier.json`。

weibo-cli 的准确表述建议是：

> 当本机已安装、当前账号已授权且存在可用只读命令时，Skill 可以优先使用 weibo-cli；否则使用公开网页、搜索与用户提供的材料继续。当前公开网页 Demo 不调用 weibo-cli。

这比“已接入微博全部数据”更可信，也方便评委理解下一步平台接口支持能带来的增量。

## 45–60 秒 Demo 分镜

| 时长 | 画面 | 旁白重点 |
| --- | --- | --- |
| 0–5 秒 | 热搜、原帖、截图快速叠加 | 一个瓜散落在很多页面里，越翻越乱 |
| 5–12 秒 | 网页虚构案例入口 | 先看产品形态：30 秒摘要、时间线和证据卡 |
| 12–24 秒 | 在 Codex 输入一个话题与链接 | 真实热点由 Skill 建立信源池，不靠网页假装实时抓取 |
| 24–36 秒 | 展示 `confirmed / conflicting / unverified / debunked` | AI 先管理不确定性，再写结论 |
| 36–48 秒 | 九页 montage，随后放大时间线与信源页 | 结果是可编辑的 9 页 PPT，每条关键判断绑定来源 |
| 48–56 秒 | 信源台账与演讲者备注 | 原始链接、发布时间与 `[Sources]` 都能人工复核 |
| 56–60 秒 | Logo + GitHub Pages + GitHub | 吃瓜神器：把热搜变成可追溯的简报 |

不要在视频里输入一个全新话题后立刻展示预制结果；网页画面应始终标注“固定虚构案例”，真实案例的生成过程则用 Codex Skill 实录。

## 可直接发布的参赛微博

```text
#微博VibeLab# #VibeSocial# #weibo-cli#

【吃瓜神器 Chigua Lens】
30 秒先看结论，9 页理清来龙去脉，每条关键判断都能回到信源。

一个热搜往往散落在原帖、视频、转发文案和公开报道里。来回翻很多页，还是容易把“网友解读”看成“当事人确认”。

所以我做了一个面向微博热点阅读场景的 Codex Skill。输入热搜词、微博链接、截图或一组公开材料，它会先建立信源池，再把内容分成：

• 已确认
• 说法冲突
• 尚未证实
• 已辟谣

最后生成：

• 9 页可编辑吃瓜简报 PPT
• 一份可追溯的信源台账
• 一份可继续生成网页、PDF 或长图的 dossier.json

我最在意的不是让 AI “更会下结论”，而是让它知道什么暂时不能下结论：关键判断绑定 sourceIds，PPT 演讲者备注保留 [Sources]，无法确认的内容不会改写成肯定句。

网页是固定虚构案例的概念 Demo；真实热点由 Codex Skill 处理。weibo-cli 在本机已安装、已授权且存在可用只读命令时可以优先使用，公开 Demo 不会假装实时抓取微博。

在线 Demo：https://nutllwhy.github.io/chigua-lens/
GitHub：https://github.com/nutllwhy/chigua-lens

这是公开信息整理，不代表司法、监管或事实认定；真实话题发布前仍需人工复核。
```
